# PF005 阶梯：找这台机器不积压的最高 TPS

流量和配置同 `PF004_mixed_1h`（5 个营销客户、5 个 OTP 客户，营销 80%、OTP 20%，营销通道 RTVM1、OTP 通道 RTVO1，都不限速）。每档预热 60 秒、压 10 分钟、排空 3 分钟；`soak.tps` 由驱动脚本按档改成 3000、3500、4000、4500，每档前清空 Redis、MySQL 并重启 a2p；压测时停掉 Redis 从库。

判断：负载稳定期间（预热以后）各段积压的总和是否一直在涨。结果见 `docs/5000TPS多主测试慢的环节分析.md`。

2026-11-18 第二轮：每个客户 6 个 bind（`soak.binds=6`，客户 `SessionNumber=6`），每个通道 6 个 bind（两个 Client 各 3 个，`SessionNumber=3`）；档位 3000、3500、4000、4500、5000。
