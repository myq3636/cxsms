# 模块动态扩缩容预发演练手册

2026-11-06

本手册是《模块动态扩缩容设计.md》第 15 节的第 7 步：在接近线上的预发环境、接近线上的流量下，把第 1～6 步做的东西按线上的操作方式走一遍。共 56 条用例（P0 40 条），按 P0 → P2 执行；**P0 全部通过才能在线上开启 `ModuleRegistryEnable` 并使用 `a2pctl` 扩缩容**。「本地」列标 ✓ 的用例在本机回归里已有覆盖（用例名写在括号里），预发仍要按业务表现复核。

相关文档：[模块动态扩缩容设计.md](模块动态扩缩容设计.md)（第 17 节是操作手册）、[消息ID防重复设计.md](消息ID防重复设计.md)、[配置项说明.md](配置项说明.md)

## 测试前准备

- **版本**：包含提交 `e6a8cbc` 及之前的全部扩缩容提交的 a2p.jar。
- **部署**：尽量和线上一致：3 个 Core（`CoreShard` 0-5 / 6-10 / 11-15，`TotalShards=16`），2 个 SMPP Client（`ClientShard` 0-7 / 8-15），1 个 HTTP Client（0-15），SMPP Server 至少 2 个、前面有负载均衡，HTTP Server 2 个。至少有一台机器跑两个以上模块（同一个 `NodeID`）。
- **为演练准备的空闲名字**：`CoreEngine4`、`MultiSmppClient3`、`MultiSmppServer3`，先写进 `a2p_modules.conf`（启用列先写 0 也可以，启动脚本要用的话写 1），编号不能和现有模块相同。
- **流量**：压测工具按线上峰值的比例持续发 MT（建议单个 Server 2000～4000 TPS），覆盖 SMPP 客户和 HTTP 客户，供应商回 DR，有 MO。每条 MT 的 `msgId` 能在压测工具、供应商侧、CDR 三处对账。
- **测试客户**：

  | 代号 | 用途 |
  | --- | --- |
  | T-Y | SMPP 客户，同时连两个 Server（经负载均衡） |
  | T-X | SMPP 客户，只连一条（会被某个 Server 独占） |
  | T-P | SMPP 客户，`SmppServerModules` 只允许一个 Server |
  | T-H | HTTP 客户 |
  | V-S | SMPP 供应商，`SessionNumber` 为 4，`SMSOptionOutgoingThrottlingNum` 有值 |
  | V-H | HTTP 供应商 |

- **备份**：`GmmsConfig.properties`、`a2p_modules.conf`、cm.cfg；Redis 里 `system:core:shards:*`、`system:client:shards:*`、`system:module*` 的现值（`redis-cli --scan --pattern 'system:*shards*'`）。
- **执行记录**：每条用例记录开始结束时间、`a2pctl` 的完整输出、相关模块日志截取、对账结果。

### a2pctl 怎么运行

和模块用同一个 jar、同一个 `a2p_home`，在能连 Redis 的任意一台机器上运行。下面写成 `a2pctl`：

```bash
alias a2pctl='java -Da2p_home=$A2P_HOME/ -Dlog4j.configurationFile=$A2P_HOME/conf/log4j2.xml -cp "<和启动脚本相同的 classpath>" com.king.gmms.ha.A2pCtl'
```

它读这个 `a2p_home` 的 `Gmms/GmmsConfig.properties`（Redis 地址、`TotalShards`、`ModuleShard*`）、`conf/cm.cfg`（容量检查、`SmppServerModules`）、`conf/a2p_modules.conf`（`init`）。所以要用线上同一份配置。

### 演练用的配置

预发先用默认值；第 J 组的用例会临时调小 `ModuleShardConfirmSeconds`。不需要的项不要加。

| 配置 | 默认 | 演练 |
| --- | --- | --- |
| `ModuleRegistryEnable` | `false` | A-02 之后所有模块改为 `true`（重启生效） |
| `ModuleStatusTTLSeconds` | `30` | 不改 |
| `ModuleStopMaxWaitSeconds` | `4` | 不改，小于停止脚本的 5 秒 |
| `ModuleDrainMaxSeconds` | `600` | 不改 |
| `ModuleDrainDrWaitSeconds` | `30` | 不改 |
| `ModuleDrainSessionIntervalMs` | `1000` | 按 Server 上的会话数调，会话数 × 间隔就是断开全部会话的时间 |
| `ModuleShardConfirmSeconds` / `ModuleShardIntervalSeconds` / `ModuleOpLockSeconds` | `30` / `10` / `60` | 只有 `a2pctl` 读 |

## 关键日志和查看命令

| 日志 | 含义 |
| --- | --- |
| `[MODULE-REG] version N in use: M modules, active [...]` | 模块用上了注册表的第 N 版；所有模块的 N 应该一致 |
| `[MODULE-REG] X must not start: ...` | 编号冲突，或同名模块在另一个 `NodeID` 上运行，**进程退出** |
| `[MODULE-REG] X is JOINING: it reads results, inbound DRs and held MTs once ACTIVE` | 新 Core 先不读这三类流 |
| `[DRAIN] X starts draining` / `[DRAIN] ... no shard left: stopped reading` / `[DRAIN] closing customer session` | 下线的各阶段 |
| `[SHARD-MOVE] s from -> to`（`a2pctl` 日志） | 一个分片迁完 |
| `[SHARD-CHECK] ERROR ... owned by no node` | 有分片没人消费，**演练中出现即失败**（`a2pctl` 运行中是 INFO） |
| `[SHARD-CHECK] WARN ... owned by more than one node` | 分片重叠，**出现即失败** |
| `[DR-TRANSFER] X: moved {...}, no target {...}` | DR 转移结果 |
| `[STOP] SIGTERM: N of N jobs finished in T ms` | 优雅停机；`N of N` 以外的结果要看是哪一项没写完 |
| `[DR-ROUTE] server module=... has no heartbeat` | Core 不再把 DR 发给没有心跳的 Server |

```bash
a2pctl status                                                   # 模块、状态、节点、分片、下线进度、当前操作
redis-cli hgetall module:drain:<模块>                            # 下线进度
redis-cli --scan --pattern 'system:shards:*' | sort | while read k; do echo "$k $(redis-cli get $k)"; done   # 每个节点实际负责的分片
redis-cli --scan --pattern 'stream:mt:pending:*' | while read k; do echo "$k $(redis-cli xlen $k)"; done | sort -k2 -n | tail   # MT 积压
redis-cli --scan --pattern 'stream:dlq:*'                        # 死信，演练前后对比
```

**每条 P0 用例的通用通过条件**（用例里不再重复）：

1. 压测期间发出的 MT，供应商侧**不缺、不重复**；DR、MO 送到客户**不缺**，重复不超过一次（DR 和 MO 本来就是“最多重发一次”）。
2. 没有新的 `stream:dlq:*` 条目；没有 2700（可能已发出）以外的新增失败状态，2700 只允许出现在用例写明的地方。
3. 没有 `[SHARD-CHECK]` ERROR/WARN，操作结束后 `system:shards:*` 覆盖 0-15、不重叠。
4. 操作结束后，所有模块日志里 `[MODULE-REG] version` 一致。

## 已知限制（演练时不算失败，但要记录影响）

- `a2pctl resume` 加 Client 时不等供应商连接建立（E-03 人工确认）。
- 迁一个分片时不等旧节点把已读的消息处理完，靠租约和自动重投保护（设计稿 6.1）。
- 容量检查只看 SMPP 连接数和外发 TPS；Core 放行速率不显示；按节点限速，不是全局限速。
- Server 断开会话后，剩下的 DR 晚一轮重试，细分失败状态重发时变成 UNKNOWN（`DEF-C5`）。
- HTTP 外发结果写不进 Redis 时，补写超过 `CoreOutboundRespTimeoutMs`（180 秒）的那部分由 Core 报 2700，是否重发看重试码（和 SMPP 相同，见 `HTTP外发结果写入失败重复发送修复设计.md`）。
