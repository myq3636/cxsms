## 1. 功能点

| # | 功能 | 配置（cm，客户上） | 生效位置 |
|---|---|---|---|
| F1 | 号码 24 小时发送上限按国家设置 | `SMSOptionRecipientMaxSendCountIn24H`、`SMSOptionRecipientMaxSendCountIn24HByCountry` | 三个 HTTP 入口、Core（SMPP 客户）、长短信合并后（SyncSubmitRouter） |
| F2 | `CustomerTypeBySender`（PA / NonPA）按国家生效 | `CustomerTypeBySender`、`SMSOptionCustomerTypeCountry` | Core 的发送方检查 |
| F3 | 发送方黑白名单按集合查找 | `senderactiondir` 下的 `*_sender_blacklist.cfg`、`*_sender_whitelist.cfg`（格式不变） | Core 的发送方检查、供应商发送方白名单检查 |
| F4 | 内容替换成号码后 N 位 | `SMSOptionContentReplacementPolicy` 里的 `{@phone#N}` 规则 | Core |
| F5 | 模板验证码去空格 | 路由的 `ReplaceContentByTemplate`、客户的 `SMSOptionTemplateCodeRegex` | Core |

### F1 号码 24 小时发送上限

```
SMSOptionRecipientMaxSendCountIn24H: 3
SMSOptionRecipientMaxSendCountIn24HByCountry: (Country=CN,MaxCount=2);(Country=SG,MaxCount=0)
```

- 国家用两位 ISO 代码（大小写都可以），由接收号码解析出来（libphonenumber）。
- 列表里没有的国家，用 `SMSOptionRecipientMaxSendCountIn24H`。
- `MaxCount=0` 表示这个国家**不限**。
- 列表写错（国家代码不存在、负数、重复、缺字段、未知属性）时整个列表不用，打一行 ERROR，所有国家按默认值。
- 超过上限：提交状态 2122（`RECIPIENT_ERROR_BY_MAX_COUNT`），rssid 记为 `BlackholeSsid`；客户收到的 DR 是 **10403（`UNDELIVERY_DAILY_LIMIT`）**。
- 计数器是状态 Redis 里的 `Duplicate:{号码}`，24 小时过期。**按号码计，不分客户**。
- Core 里同一条消息重新投递（处理它的 Core 在确认前挂了）**只计一次**（`StreamAttempt.countOnce`）；HTTP 入口每条消息计一次。

### F2 CustomerTypeBySender 按国家生效

```
CustomerTypeBySender: PA                 # 默认 NonPA
SMSOptionCustomerTypeCountry: 353        # 号码前缀，逗号分隔；all 为所有国家；不配 = 65
```

| 客户配置 | 发往新加坡 65 | 发往爱尔兰 353 | 其他国家 |
|---|---|---|---|
| 不配 `SMSOptionCustomerTypeCountry` | 按 `CustomerTypeBySender` | 普通检查 | 普通检查 |
| PA + `353` | **NonPA** | PA | 普通检查 |
| PA + `65,353` | PA | PA | 普通检查 |
| PA + `65` | PA | 普通检查 | 普通检查 |
| NonPA + `353` | NonPA | NonPA | 普通检查 |
| `all` | 按 `CustomerTypeBySender` | 同左 | 同左 |
| VIP | 不检查 | 不检查 | 不检查 |

各种检查的规则：

| 检查 | 黑名单 | 白名单 |
|---|---|---|
| NonPA | 只查全局（-1） | 只查客户自己的（wl 原样发、rp 替换后发），没命中就拒绝（10802），不查默认白名单 |
| PA / 普通检查 | 查客户的和全局的 | 客户自己的白名单有这个国家的条目时只按它判断；没有时查默认（-1）白名单：wl 原样发 → rp 替换后发 → 拒绝；默认白名单也没有这个国家的条目（也没有 `all:` 规则）时**放行** |

在黑名单里的拒绝码是 10801（`REJECTED_SDBL`），白名单没命中的拒绝码是 10802（`REJECTED_SDWL`）。

### F3 发送方黑白名单按集合查找

- 发送方和名单里某一条**完全相等**才算命中：区分大小写，特殊字符、空格都按原样比较，`.`、`*`、`[]`、`$`、`\` 等不是通配符。
- 名单值不去掉空格：`86: LEAD` 记成 ` LEAD`，只拦发送方 ` LEAD`。
- 白名单分客户：客户文件里的规则（包括 rp 的替换值）只对这个客户生效，`-1_sender_whitelist.cfg` 的规则对所有客户生效。原来 rp 的替换值所有客户共用一张表，会互相覆盖。
- 和原来不同的一处：名单里写了 `|` 的条目，原来会被当成“或”拆开，现在按原样比较。
- 性能：查找耗时和名单大小无关。名单 5000 条时一次检查约 3 微秒，原来扫正则要 30～70 微秒。
- 文件格式、加载、重新加载、导出到 Redis（`senderBlacklist`、`senderWhitelist`）都不变。

### F4 号码后 N 位

```
SMSOptionContentReplacementPolicy: (prefix=86,value=\{@phone#(\d+)\}:\{@phone#(\d+)\})
```

- 正则和替换写成一样，表示“按号码替换”：内容里的 `{@phone#N}` 换成接收号码的后 N 位。
- 只对 `prefix=号码前缀` 的规则生效，`prefix=all` 的规则不支持。
- N 的范围是 1～18；号码不够 N 位时用整个号码；N 超过 18 时这一条不替换，打 ERROR，消息照常发。
- 正则里**不能有逗号**（多值项的分隔符），不能写 `\d{1,2}`。

### F5 模板验证码去空格

从内容里提取出的验证码去掉 `-` 和空格后，填进模板的 `$shortcode$`，例如 `12 34` → `1234`。用 `SMSOptionTemplateCodeRegex` 指定能匹配带空格编码的正则。

## 5. 上线注意

- **PA / NonPA 的变化**：配了 `SMSOptionCustomerTypeCountry` 的客户，没列出的 65 按 NonPA。只想对爱尔兰 PA、新加坡也保持 PA 的，要配 `65,353`。
- **NonPA 发往爱尔兰直接拒绝**，不再按默认白名单的 rp 替换。需要替换的客户要配成 PA，或者在客户自己的白名单里写 rp 规则。
- **PA 和普通检查在默认白名单没有这个国家的条目时放行**。某个国家要限制发送方，就要在默认白名单里给它配条目。
- **号码上限的计数器按号码计、不分客户**：多个客户发同一个号码，会共用一个计数。
- **名单里写了 `|` 的条目**，原来会被当成两条，现在按原样比较。上线前可以在名单文件里查一下有没有 `|`。
- 没有新增 GmmsConfig 配置项。cm 选项随 `RELOAD_CUSTOMER` 生效，名单文件随原来的名单重新加载生效。
