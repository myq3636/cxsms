# 网关指标采集工具部署配置说明（gw-metrics-agent）

> 日期：2026-11-26。说明 gw-metrics-agent 的构建、网关侧的前提配置、安装、配置项、启动停止、运维命令、升级、排查和卸载。
> 设计见《网关指标采集工具设计》，代码在 `tools/gw-metrics-agent/`。Portal 一侧的部署见 Portal 工程的 `docs/网关监控部署说明.md`，页面怎么看见 `docs/网关监控图使用说明.md`。

## 1. 它做什么

- 每台网关机器部署一个，以常驻进程运行（JDK 17，Spring Boot，不开端口）。
- 跟读这台机器上各模块的 metrics 日志 `log/{模块}_metrics.log`，以及各模块主日志里的 `[METRICS-ALERT]` 告警行，把每 30 秒一个的窗口批量推送给 Portal 的接收接口（HTTPS，HMAC-SHA256 签名）。
- **只读日志**：不写、不截短、不改名、不加锁，不连网关的 Redis 和数据库，不影响网关写日志和 log4j 滚动。
- Portal 确认收到后才记下读到的位置；Portal 不可用时退避重试并暂停读取，日志文件本身就是缓冲，日志保留期（7 天）内都能补齐。

## 2. 网关侧的前提配置

采集程序本身不改网关，但网关要先按下面配置，否则没有数据或数据不全。

### 2.1 log4j2：每个模块一个 metrics 文件

`conf/log4j2.xml` 的 metrics 部分按《性能监控指标说明》8.3 节配置（测试服务器 2026-11-25 已改）：

- `fileName="$${sys:a2p_home}log/$${sys:module}_metrics.log"`：每个模块一个文件（几个模块写同一个文件时，滚动会丢行）。
- `filePattern="${filepath}/$${sys:module}_metrics.log.%d{yyyy-MM-dd}-%i.gz"`：滚动到 `log/previous/`，带 `-%i`（同一天多次按大小滚动不互相覆盖）。
- `Delete` 清理 7 天前的 `*_metrics.log.*.gz`（采集程序停机 7 天以内还能补读）。
- `metrics.logger` 的级别是 `info`。

### 2.2 GmmsConfig（`Gmms/GmmsConfig.properties`，都可以热加载）

| 配置 | 要求 | 说明 |
| --- | --- | --- |
| `Metrics.Enable` | `true` | 总开关 |
| `Metrics.LogLevel` | `INFO` | **必须不高于 log4j2 里 `metrics.logger` 的级别**。测试服务器原来是 `DEBUG`，而 logger 是 `info`，结果一行指标都不写 |
| `Metrics.Format` | `json` | kv 格式的行采集程序不认（跳过并计数） |
| `Metrics.PrintGauge` | `true` | 否则积压、待确认、资源这些瞬时值都没有 |
| `Metrics.ReportIntervalSeconds` | `30`（不超过 100） | 窗口秒数；按 ssid 的条数换算要求窗口不超过 100 秒 |
| `Metrics.Ssid.Enable` | 需要“客户/通道监控”时 `true` | 会增加日志量（客户多时每个模块每天几百 MB），上线前先量一次 |
| `DB.PoolStats.Enable` | 需要 DB 连接池曲线时 `true` | |
| `Metrics.Alert.StreamLagMs` 等 | 按现场设置 | 告警阈值，默认 0 不检查；不设就没有告警事件。建议值见《性能监控指标说明》8.2 |

## 3. 构建

在任意一台装有 JDK 17、能访问 Maven 中央仓库（或内部镜像）的机器上：

```
cd tools/gw-metrics-agent
./mvnw -B clean package           # 产物 target/gw-metrics-agent-<版本>.jar（约 18 MB），25 项测试随构建一起跑
```

- 工程带 Maven Wrapper，不用另外装 Maven；第一次会下载 Maven 3.9.16 和依赖。
- 不想用 `~/.m2` 时加 `-Dmaven.repo.local=<目录>`，Maven 本身下载到 `MAVEN_USER_HOME`。
- jar 是自包含的，部署的机器只需要 JDK 17，不需要访问 Maven 仓库。

## 4. 安装（每台网关机器）

### 4.1 目录

```
/usr/local/a2p/metrics-agent/
  gw-metrics-agent.jar            # 构建产物改名为不带版本号，升级时直接替换
  config/application.yml          # 本机配置（由 tools/gw-metrics-agent/deploy/application.yml.sample 改）
  agent.secret                    # 签名密钥，一行，权限 600
  state/positions.json            # 读到的位置（自动生成，别手改；要改用 --reset）
  state/agent.lock                # 单实例锁
  log/agent.log                   # 自身日志（按 10 MB 滚动，总量不超过 100 MB）
```

### 4.2 步骤

1. 创建目录，拷入 jar（改名为 `gw-metrics-agent.jar`）。
2. 生成密钥：`head -c 32 /dev/urandom | base64 | tr -d '/+=' > agent.secret && chmod 600 agent.secret`。
3. 把 `主机名:密钥` 交给 Portal 管理员，加进 Portal 的 `gw.metrics.agents`（主机名是下面的 `agent.host`，不填就是本机名 `hostname`）。
4. 写 `config/application.yml`（第 5 节），至少填 `agent.portal.url`。
5. 检查：`cd /usr/local/a2p/metrics-agent && java -jar gw-metrics-agent.jar --check`，最后一行是 `OK`（第 7 节）。
6. 安装 systemd 服务（4.3）并启动。

### 4.3 systemd 服务

仓库里的 `tools/gw-metrics-agent/deploy/gw-metrics-agent.service`，拷到 `/etc/systemd/system/`：

```ini
[Unit]
Description=Gateway metrics agent (reads metrics logs, posts to Portal)
After=network-online.target

[Service]
WorkingDirectory=/usr/local/a2p/metrics-agent
ExecStart=/usr/bin/java -Xms64m -Xmx128m -XX:+UseSerialGC -XX:TieredStopAtLevel=1 -jar gw-metrics-agent.jar
SuccessExitStatus=143
Restart=always
RestartSec=10
TimeoutStopSec=30
Nice=10
CPUQuota=20%
MemoryLimit=384M
IOSchedulingClass=idle

[Install]
WantedBy=multi-user.target
```

```
systemctl daemon-reload
systemctl enable --now gw-metrics-agent
systemctl status gw-metrics-agent
```

- `ExecStart` 里的 java 路径要是 JDK 17（`java -version` 确认）；网关和采集程序可以用同一个 JDK。
- 资源限制：CPU 不超过 20%，内存不超过 384 MB，优先级低于网关模块。实测常驻内存约 120–250 MB，CPU 在单核的 1–2% 以内。

## 5. 配置项（`config/application.yml`）

只写和默认值不同的项；默认值在 jar 内的 `application.yml`。任何一项都可以临时用命令行 `--agent.xxx=值` 覆盖。**改了要重启才生效**（重启很快，会从原来的位置续读）。

```yaml
agent:
  portal:
    url: https://portal.example.com/api/v1/gw/metrics/ingest    # 必填
  host: a2p-gw-1                                               # 可选，默认本机名
```

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `agent.portal.url` | 无，必填 | Portal 接收接口的完整地址，路径固定是 `/api/v1/gw/metrics/ingest` |
| `agent.portal.timeout` | `10s` | 连接和单次请求的超时 |
| `agent.portal.trust-store` / `trust-store-password` | 空 | Portal 用自签证书时的信任库（p12 或 jks）；没有“跳过证书校验”的开关 |
| `agent.host` | 本机名 | 发给 Portal 的机器名（`X-Agent-Host`），Portal 按它找密钥，必须和 `gw.metrics.agents` 里的一致 |
| `agent.secret-file` | `agent.secret` | 签名密钥文件 |
| `agent.state-dir` | `state` | 读到的位置和单实例锁 |
| `agent.log-dir` | `/usr/local/a2p/log` | 网关日志目录 |
| `agent.metrics.include` | `*_metrics.log` | 要采集的 metrics 文件 |
| `agent.alert.include` / `exclude` | `*.log` / `*_metrics.log,*_gc.log*,*_smpp_pdu.log,*.out` | 扫 `[METRICS-ALERT]` 的主日志；`include` 设为空字符串就不采集告警 |
| `agent.alert.zone` | 系统时区 | 主日志时间戳的时区 |
| `agent.rolled.dir` | `/usr/local/a2p/log/previous` | 滚动出去的文件所在目录，和 log4j2 的 `filePattern` 一致 |
| `agent.rolled.pattern` | `{name}.{date}-{i}.gz` | 滚动后的文件名规则 |
| `agent.rolled.max-hold` | `60s` | 滚动后的旧文件句柄最多保留多久（超过就改读 .gz），避免长时间占住已删除文件的磁盘空间 |
| `agent.start.metrics` / `start.alert` | `beginning` / `end` | 没有记录位置时从文件开头还是末尾读：第一次启动时 metrics 从头读（补当天），告警从末尾读（不扫历史） |
| `agent.send-interval` | `10s` | 发送间隔，积压超过一批时立即发 |
| `agent.heartbeat-interval` | `30s` | 空闲时单独发心跳的间隔 |
| `agent.batch.max-windows` / `max-size` | `500` / `8MB` | 一批的上限 |
| `agent.outbox.max-windows` / `max-size` | `20000` / `50MB` | 待发队列的上限，满了暂停读取 |
| `agent.assemble-idle` | `5s` | 一个窗口多久没有新行就算完成 |
| `agent.read.backfill-mbps` | `20` | 读滚动文件、远落后于文件末尾时的限速（MB/s，解压前），避免补读时和网关抢磁盘；0 不限 |
| `agent.lag-warn` | `5d` | 未读数据早于多久就在心跳里告警（日志只保留 7 天） |

## 6. 启动、停止、状态

| 操作 | 命令 |
| --- | --- |
| 启动 / 停止 / 重启 | `systemctl start|stop|restart gw-metrics-agent` |
| 状态 | `systemctl status gw-metrics-agent`；`tail -f /usr/local/a2p/metrics-agent/log/agent.log` |
| 停止时 | 收到 SIGTERM 后先停读，把待发队列最多再发 10 秒，保存位置再退出（退出码 143 是正常的）；被强杀也只是重读最后一批，Portal 会去重 |

## 7. 运维命令

在安装目录下执行，都是一次性的，执行完就退出：

| 命令 | 用途 |
| --- | --- |
| `java -jar gw-metrics-agent.jar --check` | 检查配置；列出找到的文件、读到的位置、滞后字节数、能找到的滚动文件；看每个 metrics 文件最后 256 KB 里有没有 kv 格式或解析失败的行；向 Portal 发一个心跳。退出码 0 = 正常 |
| `java -jar gw-metrics-agent.jar --dry-run --limit=5` | 从当前位置解析，把将要发送的窗口打印成 JSON，不发送、不改位置（上线前对照日志核对） |
| `java -jar gw-metrics-agent.jar --replay='CoreEngine1_metrics.log.2026-11-2*' --from='2026-11-25 10:00' --to='2026-11-25 12:00'` | 把旧文件（含 .gz）在指定时间内重发一遍，用于补数据；Portal 去重，可以和常驻进程同时运行 |
| `java -jar gw-metrics-agent.jar --reset=CoreEngine1_metrics.log --to=end` | 把某个文件的读取位置重置到开头（`begin`）或末尾（`end`）；要先停服务 |

## 8. 升级与卸载

- **升级**：替换 `gw-metrics-agent.jar`，`systemctl restart gw-metrics-agent`，从原来的位置续读。
- **卸载**：`systemctl disable --now gw-metrics-agent`，删除服务文件和 `/usr/local/a2p/metrics-agent`；从 Portal 的 `gw.metrics.agents` 去掉这台机器。网关不受影响。

## 9. 排查

| 现象 | 原因和处理 |
| --- | --- |
| `--check` 显示 `Portal: HTTP 401` | 主机名或密钥对不上：`agent.host` 和 `agent.secret` 要和 Portal `gw.metrics.agents` 里的那一组完全一致 |
| `Portal: java.net.ConnectException` / 超时 | 网络不通、地址或端口不对、防火墙或安全组没放行；用 `curl -v <url>` 试 |
| `Portal: HTTP 503` | Portal 关闭了接收（`gw.metrics.ingest.enabled=false`）或数据库繁忙；采集程序会自动重试 |
| `Portal: HTTP 413` | 一批太大；采集程序会自动减半；频繁出现时调小 `agent.batch.max-*` 或调大 Portal 的 `gw.metrics.ingest.max-body-mb` 和反向代理的上限 |
| `--check` 里 metrics 文件 0 行 | 网关没写指标：看 2.2 的 `Metrics.LogLevel`（要 `INFO`）和 `Metrics.Enable`，以及 log4j2 是否按模块拆了文件 |
| `--check` 里有 kv 行 | 网关是 `Metrics.Format=kv`，改成 `json` |
| 日志里 `lines not understood` | 指标行格式不对，`--check` 会显示样本 |
| 日志里 `no data from ... to ...`（缺口） | 采集程序停机太久，滚动文件在读到之前被清理了；这段数据无法补回，Portal 的 `gw_metric_gap` 表有记录 |
| 日志里 `rolled over, reading the rest of the old file` | 正常：log4j 滚动了文件，采集程序读完旧文件再切换 |
| 日志里 `shorter ... truncated, read again from its start` | 有人清空了日志文件（例如压测脚本 `perf_clean.sh`），采集程序从头重读，重复的窗口由 Portal 去重 |
| `another gw-metrics-agent holds state/agent.lock` | 已经有一个在运行（`--reset` 时要先停服务） |
| Portal 页面显示“采集中断” | 这台机器的采集程序超过 60 秒没有心跳：看 `systemctl status` 和 `log/agent.log` |
