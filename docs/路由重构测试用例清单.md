**测试方式：**

| 方式 | 说明 |
|---|---|
| 单元 | 在测试进程里直接调用 `RuleRouter` / 加载代码，不起模块（规则解析、索引、匹配、校验） |
| Core IT | 真实 Core（`CoreRouteIT`、`CoreRetryIT` 的做法）：消息写进 `stream:mt:pending`，看写到哪个 `stream:mt:routed:{rssid}:*`；外发结果由测试直接写 `stream:core:results`（指定状态码），模拟 submit 失败 |
| 链路 | 三个进程（Server、Core、Client，`PathChainIT` 的做法），FakeSmsc 按账户返回指定的 submit_sm_resp 状态 / DR |
| 工具 | a2pctl 转换、试算子命令 |

**通用前提（除非用例另说）：** 客户 C1（ossid 8801）；通道 V1～V13（rssid 81～93，都在同一个 A2P）；每个通道 `SMSOptionSubmitRetryCode` 配了“可改道码”`10200,10203`，失败码 `10208` 不在里面；号码 `8613800000000`；发送方 `OTP`；没有开二次路由、没有 MNP。
