# 回归测试说明

长期回归放在仓库的 `regression/` 下，覆盖 Core、Client、Server 和配置热加载。

## 运行

```bash
export JAVA_HOME=/path/to/jdk-17          # JDK 17，不设时用 PATH 里的 javac
export REDIS_SERVER=/path/to/redis-server # 127.0.0.1:16379 没有 Redis 时用它启动，不设时用 PATH 里的
export REDIS_CLI=/path/to/redis-cli

regression/run.sh                         # 全部套件
regression/run.sh ServerFuncIT MultiServerIT   # 指定套件
```

- **会清空 16379 上的 Redis**（套件启动时 `FLUSHALL`），不要指向有数据的实例。
- 全量运行耗时较长，主要是 Server 和 Core 的集成用例。`MultiServerIT` 同时启动 3 个 JVM，建议至少 4GB 内存。
- 退出码：0 表示没有新失败；1 表示有套件失败；2 表示编译失败。
- 结果在 `regression/.work/results/`：`summary.txt` 是汇总，`{套件}.txt` 是每项检查，`logs/` 是应用日志。`.work` 不提交。

## 结果怎么看

| 输出 | 含义 | 影响退出码 |
|---|---|---|
| `PASS` | 通过 | 否 |
| `FAIL` | **新失败，要处理** | 是 |
| `KNOWN` | 已知缺陷，登记在 `regression/known-defects.txt` | 否 |
| `FIXED` | 已登记的项通过了。确认修好后从清单删除；竞争类缺陷可能偶尔通过 | 否 |

修复缺陷后要从 `known-defects.txt` 删除对应的检查，之后它再失败就算回归。

## 目录

| 路径 | 内容 |
|---|---|
| `regression/run.sh` | 编译、准备配置、运行、汇总 |
| `regression/suites.txt` | 套件清单：名称、类、模式 |
| `regression/known-defects.txt` | 已知缺陷 |
| `regression/test/` | 测试代码 |
| `regression/home/`、`regression/home-nosr/` | 测试配置模板，每个套件运行前复制一份，互不影响 |

## 新增套件

1. 在 `regression/test/it/` 写一个继承 `ItSupport` 的类，用 `check(条件, "ID 说明")` 判定，最后调用 `exit()`。
2. 在 `suites.txt` 加一行。模式：`unit`（不启动系统）、`it`（Core）、`it-server`（Server）、`it-mod:{模块}`（带模块清单）、`it-tls`（TLS）、`it-multi`（多 Server 进程）。

`a2p_modules.conf` 每行第一列是启用标记，必须是 `1`，不是节点号；写错时这个模块不会加载，reload 时也不会建连接。

检查结果时要确认连接真的有响应：连接关闭时 `read` 返回 `cmd=-1`，只判断 `status==0` 会造成假通过。

## 不在回归范围

见《SMPP-Server功能测试清单》第十一节：2 万条连接、慢客户、多节点客户（`MN`）、TLS 客户端证书等。
